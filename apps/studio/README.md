# AnimeList Studio

Desktop GUI for managing your AnimeList data store. Built with Tauri (Rust) and Nuxt.

## Commands

This app is orchestrated with [moon](https://moonrepo.dev/). Run the tasks from the workspace root.

### Develop

Runs the Nuxt dev server (with HMR) and launches the native window pointing at it.

```
moon run studio:tauri -- dev
```

### Build

Produces the release binary. `tauri build` runs `pnpm generate` first, so the frontend assets are generated and embedded automatically.

```
moon run studio:tauri -- build
```

The binary is written to `target/release/animelist-studio` at the monorepo root.

### Type-check the Rust crate

Compiles only the Rust side. Note this does **not** generate or embed the frontend, so the resulting binary will not serve the UI.

```
moon run studio:cargo -- check
```

If you need a working binary from `cargo build`, generate the frontend assets first:

```
moon run studio:pnpm -- run generate
moon run studio:cargo -- build
```

The compiled binary is written to `target/debug/animelist-studio` (or `target/release/animelist-studio`) at the monorepo root.

## Frontend modes

The window loads the frontend in one of two ways depending on how it was built:

- **Dev** (`tauri dev`): loads the live Nuxt dev server from `devUrl` (`http://localhost:3000`).
- **Release** (`tauri build`): loads the static assets embedded from `frontendDist` (`../dist`), generated by `pnpm generate`.

A plain `cargo build` skips the frontend orchestration entirely, which is why the produced binary shows no UI unless the assets were generated beforehand.
